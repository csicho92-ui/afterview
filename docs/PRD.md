# AFTERVIEW — Product Requirements Document

**제품명:** AFTERVIEW  
**한 줄 정의:** 면접의 기억을 구조화하고 AI로 객관적인 회고를 돕는 웹 서비스  
**문서 버전:** v1.0  
**작성일:** 2026.10.20  
**개발 단계:** MVP  
**배포 형태:** 공개 웹 서비스  
**개발 목표:** GitHub 저장소 관리 및 정적 웹 호스팅 배포

---

## 1. 제품 개요

### 1.1 문제 정의

면접이 끝난 후 지원자는 자신이 어떤 질문을 받았고 어떻게 답변했는지 정확하게 기억하기 어렵다.

특히 시간이 지나면서 면접관의 반응, 당시 감정, 답변의 맥락이 사라진다.

ChatGPT 같은 AI를 활용해 면접을 분석하려 해도 사용자가 면접 경험을 처음부터 설명해야 하며, 정보를 체계적으로 정리하지 않으면 분석 품질이 떨어질 수 있다.

기존 면접 준비 서비스는 예상 질문과 모범 답변 제공에 집중하는 경우가 많다.

AFTERVIEW는 면접이 끝난 이후의 경험에 집중한다.

### 1.2 제품 비전

**"면접이 끝난 뒤, 기억을 기록으로. 기록을 다음 기회로."**

면접에서 받은 질문과 실제 답변, 면접관 반응, 조직에 대한 인상을 단계적으로 기록하고 AI가 분석하기 적합한 데이터로 변환한다.

궁극적으로 사용자가 자신의 면접 역량을 개선하고, 지원 조직에 대한 적합성까지 판단할 수 있도록 돕는다.

### 1.3 핵심 가치

- **기록:** 면접 경험이 사라지기 전에 보존한다.
- **구조화:** 산발적인 기억을 질문과 답변 중심으로 정리한다.
- **분석:** AI를 활용해 강점과 보완점을 검토한다.
- **성찰:** 합격 가능성뿐 아니라 자신에게 적합한 조직인지 생각한다.
- **축적:** 여러 면접의 기록을 모아 장기적인 성장 과정을 확인한다.

## 2. 대상 사용자

### Primary Persona

취업이나 이직을 준비하는 구직자.

- 신입 지원자
- 경력직 이직 준비자
- 직무 전환 지원자
- 면접을 자주 진행하는 구직자

### 사용자 니즈

"면접을 보고 나왔는데 내가 잘 대답한 건지 모르겠어."

"기억나는 질문들을 기록해서 AI한테 평가받고 싶어."

"다음 면접에서는 어떤 부분을 개선해야 할지 알고 싶어."

"면접을 보면서 회사에 대한 생각이 바뀌었는데, 그 이유를 정리하고 싶어."

### 핵심 JTBD (Jobs To Be Done)

사용자가 면접을 마친 후 당시 질문, 답변, 반응을 기록하면 이를 체계적인 회고 자료와 AI 분석 프롬프트로 전환하여 다음 면접에서 더 나은 의사결정을 할 수 있도록 한다.

## 3. MVP 목표와 범위

### 3.1 MVP의 핵심 목표

사용자가 면접 경험을 기록하고, 별도의 프롬프트 작성 능력 없이 AI 분석을 요청할 수 있도록 한다.

### 3.2 MVP 필수 기능 (P0)

| ID | 기능 | 설명 |
|---|---|---|
| F01 | 면접 기록 생성 | 회사, 직무, 날짜 등 입력 |
| F02 | 실제 면접 질문 등록 | 면접관에게 받은 질문 추가 |
| F03 | 답변 및 반응 입력 | 실제 답변과 면접관 반응 기록 |
| F04 | 가이드형 회고 질문 | 웹이 추가 질문을 제시 |
| F05 | AI 프롬프트 생성 | 모든 입력을 하나의 분석 요청문으로 구성 |
| F06 | 프롬프트 복사 | 클립보드로 전체 내용 복사 |
| F07 | 프롬프트 미리보기 | AI에 전달할 내용을 사전 확인 |
| F08 | 임시 저장 및 복원 | 브라우저 내부에 작성 내용 자동 저장 |
| F09 | 기록 수정·삭제 | 기존 기록 관리 |
| F10 | 반응형 웹 | PC와 모바일 지원 |

### 3.3 MVP 보조 기능 (P1)

- 프롬프트 Markdown 파일 내보내기
- 면접 기록 JSON 백업 및 불러오기
- 사용자의 AI 회고 결과 붙여넣기 및 저장
- 질문 순서 변경
- 회고 목적에 따른 프롬프트 변경
- AI에 전달하기 전 개인정보 검토
- 여러 면접 기록 목록 조회

### 3.4 MVP 제외 기능

첫 출시에서는 다음 기능을 구현하지 않는다.

- OpenAI API 등 유료 AI 직접 연동
- 회원가입 및 로그인
- 클라우드 데이터베이스
- 면접 녹음 및 자동 음성 인식
- 실시간 AI 채팅
- 채용정보 검색 및 지원서 관리
- 합격 확률 예측
- 면접관의 표정이나 감정 자동 분석

향후 수요 검증 후 확장한다.

## 4. 서비스 정보 구조

### 4.1 화면 구성

**A. Landing / Dashboard**

서비스 소개와 기존 면접 기록을 보여주는 화면.

주요 요소:

- AFTERVIEW 로고
- "면접이 끝나고, 무엇이 남았나요?" 헤드라인
- 새 면접 기록 시작 버튼
- 최근 작성 기록
- 작성 중인 회고 이어하기
- 저장 및 개인정보 안내

**B. Interview Setup**

새 면접의 기본 정보를 입력하는 화면.

**C. Question Recorder**

실제 면접 질문과 당시 답변을 기록하는 화면.

**D. Guided Reflection**

웹이 제시하는 추가 회고 질문에 응답하는 화면.

**E. Review & Prompt**

전체 기록을 검토하고 AI 분석 프롬프트를 생성하는 화면.

**F. Interview Archive**

이전에 작성한 면접 기록을 수정하고 다시 분석하는 화면.

```text
    ↓
```

## 5. 상세 기능 명세

### 5.1 면접 기본 정보 입력

사용자에게 다음 정보를 요청한다.

| 항목 | 입력 방식 | 필수 여부 |
|---|---|---|
| 회사·기관명 | 텍스트 | 필수 |
| 지원 직무 | 텍스트 | 필수 |
| 면접 날짜 | 날짜 선택 | 선택 |
| 면접 단계 | 선택 | 선택 |
| 면접관 수 | 숫자 | 선택 |
| 면접 소요 시간 | 숫자 | 선택 |
| 면접 방식 | 대면/화상/전화/기타 | 선택 |
| 면접 분위기 | 태그 + 자유 입력 | 선택 |

면접 단계 예시:

- 1차 면접
- 2차 면접
- 최종 면접
- 실무 면접
- 임원 면접
- 기타

사용자가 정확히 모르는 항목은 건너뛸 수 있어야 한다.

입력 단계별 진행 상태를 표시한다.

### 5.2 실제 면접 질문 기록

가장 중요한 기능이다.

사용자가 면접에서 실제로 받은 질문을 자유롭게 등록할 수 있어야 한다.

한 개의 질문 카드에는 다음 필드를 제공한다.

**필드 구성**

1. 면접관이 한 질문
2. 내가 실제로 한 답변
3. 면접관의 반응
4. 당시 느낀 감정
5. 지금 생각하는 아쉬운 점
6. 추가 메모

모든 질문 카드는 독립적으로 수정·삭제할 수 있다.

질문 개수에 고정된 제한을 두지 않는다.

"질문 추가하기" 버튼으로 필요한 만큼 추가할 수 있도록 한다.

**입력 예시**

면접 질문:

"홈페이지에서 개선이 필요하다고 생각한 부분이 있나요?"

실제 답변:

"공지사항이 이미지로 게시되어 번역 기능을 사용하기 어렵다는 점을 설명했고, HTML 기반 텍스트로 개선할 것을 제안했다."

면접관 반응:

"흥미롭다는 듯한 반응을 보였다."

당시 감정:

"내가 발견한 문제가 의미 있게 받아들여졌다는 느낌이 들었다."

**UX 요구사항**

- 질문별 아코디언 카드
- 질문 복제 및 순서 변경
- 질문 일부만 입력해도 임시 저장
- 기억이 나지 않는 내용은 공란 허용
- 음성 입력 없이도 빠르게 입력 가능한 큰 텍스트 영역
- 모바일 화면에서 입력하기 편한 구조

### 5.3 가이드형 추가 회고 질문

사용자가 면접 질문을 기록한 후 웹이 추가 질문을 제시한다.

목적은 단순한 질문·답변 기록에서 놓칠 수 있는 감정과 맥락을 보완하는 것이다.

질문을 한 번에 모두 보여주기보다는 단계별로 제시한다.

**카테고리 A — 면접 경험**

- 면접 분위기는 전반적으로 어땠나요?
- 어떤 질문에서 가장 자신 있었나요?
- 어떤 질문에서 당황했나요?
- 면접관이 특별한 반응을 보인 순간이 있었나요?

**카테고리 B — 자기 평가**

- 이번 면접에서 가장 잘했다고 생각하는 점은 무엇인가요?
- 다시 답변한다면 바꾸고 싶은 부분이 있나요?
- 자신의 강점을 충분히 보여줬다고 생각하나요?

**카테고리 C — 조직 적합성**

- 면접 전 회사에 대해 기대했던 점은 무엇인가요?
- 면접을 진행하면서 생각이 바뀐 부분이 있었나요?
- 업무 범위나 처우와 관련해 우려되는 부분이 있었나요?
- 합격한다면 입사하고 싶은 마음이 있나요?

**카테고리 D — 최종 회고**

- 면접을 마친 직후의 기분은 어땠나요?
- 다음 면접에 꼭 적용하고 싶은 경험은 무엇인가요?
- AI에게 가장 자세히 분석받고 싶은 부분은 무엇인가요?

**질문 노출 규칙**

- 기본 회고에서는 핵심 질문 5개 내외를 제시한다.
- 사용자는 더 깊은 회고를 선택해 질문을 추가할 수 있다.
- 질문은 건너뛸 수 있다.
- 이미 답한 내용과 중복되는 질문은 최소화한다.
- 입력 내용이 적더라도 프롬프트 생성은 가능해야 한다.

MVP에서는 정해진 질문 목록과 선택형 분기 규칙을 사용한다. AI가 실시간으로 추가 질문을 생성하는 기능은 후속 버전에서 검토한다.

### 5.4 AI 회고 목적 선택

프롬프트 생성 전 사용자가 원하는 분석 유형을 선택한다.

**모드 1. 종합 회고**

질문별 답변 평가와 전체 면접 흐름 분석.

**모드 2. 답변 집중 분석**

질문 의도, 답변의 논리성, 설득력, 개선 방향에 집중.

**모드 3. 조직 적합성 분석**

면접에서 확인된 조직 특성, 개인의 기대와 우려, 추가 확인 사항 분석.

**모드 4. 다음 면접 준비**

이번 경험을 바탕으로 구체적인 개선점, 모범 답변, 학습 과제 생성.

모드 선택은 단일 선택 또는 복수 선택을 지원한다.

기본값은 종합 회고이다.

추가 옵션:

- 분석 톤: 균형 잡힌 / 비판적인 / 격려 중심
- 분석 깊이: 간단히 / 보통 / 상세히

분석 톤이 바뀌더라도 사실에 근거한 평가 원칙은 유지한다.

### 5.5 AI 프롬프트 생성

사용자 입력값을 정해진 템플릿에 삽입하여 하나의 Markdown 텍스트로 변환한다.

생성된 프롬프트는 다음 구조를 갖는다.

1. AI의 역할
2. 분석 목적
3. 면접 기본 정보
4. 실제 면접 질문과 답변
5. 면접관 반응
6. 사용자의 자기 평가 및 감정
7. 조직 적합성에 대한 관찰
8. 분석 지침
9. 원하는 출력 형식

**중요한 제약**

- 사용자가 작성하지 않은 답변을 AI 프롬프트에 사실처럼 추가하지 않는다.
- 모르는 정보는 '미기록'으로 처리한다.
- 사용자의 관찰과 추측을 구분한다.
- 답변 원문과 서비스가 정리한 요약을 혼동하지 않는다.
- AI 분석이 실제 면접 평가 결과를 알고 있는 것처럼 작성하지 않는다.

### 5.6 프롬프트 결과 화면

프롬프트 생성 후 다음 UI를 제공한다.

**메인 액션**

"AI 회고 프롬프트 복사하기"

**보조 액션**

- ChatGPT 열기
- Claude 열기
- Gemini 열기
- Markdown 파일 저장
- 입력 내용 수정하기

AI 서비스 열기는 해당 서비스의 공식 웹페이지를 새 탭으로 여는 방식으로 구현한다.

프롬프트는 사용자가 직접 붙여넣어야 하며, AI 서비스에 자동 전송된다고 안내해서는 안 된다.

복사 버튼을 누르면 실제로 클립보드에 텍스트가 복사되어야 한다.

복사 실패 시 텍스트 선택 및 수동 복사 기능을 제공한다.

AI에 전달하기 전 개인정보 검토 안내를 제공한다.

## 6. AI 분석 프롬프트 템플릿

아래는 실제 서비스에서 동적으로 생성할 프롬프트의 기본형이다.

### 6.1 기본 프롬프트


### 6.2 프롬프트 생성 규칙

- 각 질문에 고유 번호를 부여한다.
- 입력 순서를 유지한다.
- 미입력 항목은 생략하거나 미기록으로 표시한다.
- 분석 모드에 따라 요청 결과 항목을 변경한다.
- 기록이 부족하면 분석의 불확실성이 커질 수 있음을 안내한다.
- AI로 전달할 최종 텍스트를 반드시 사용자에게 보여준다.

### 9.1 권장 기술 스택

|---|---|

| AI Integration | 프롬프트 복사 방식 |

### 9.2 기술 구조

MVP는 백엔드 없이 실행되는 클라이언트 사이드 애플리케이션으로 구현한다.

사용자 입력값과 회고 기록은 브라우저 로컬 저장소에 저장한다.

프롬프트 생성 로직 역시 브라우저에서 실행한다.

사용자가 복사한 프롬프트를 외부 AI 서비스에 직접 입력하는 방식으로 운영한다.

**보안 요구사항**

- API 키를 클라이언트 코드에 포함하지 않는다.
- 입력 데이터를 자체 서버에 자동 업로드하지 않는다.
- 외부 분석 도구나 추적 스크립트는 MVP에 포함하지 않는다.
- 사용자 입력을 화면에 표시할 때 적절한 이스케이프 처리를 적용한다.
- 프롬프트를 외부 서비스에 전달하기 전 개인정보 확인 안내를 제공한다.
- 민감한 개인정보가 포함된 경우 사용자가 직접 삭제하거나 익명화할 수 있도록 한다.

LocalStorage는 암호화된 비밀 저장소가 아니므로 공용 기기에서 이용할 때 주의가 필요하다는 안내를 제공한다.

브라우저 데이터 삭제나 기기 변경으로 기록이 사라질 수 있으므로 JSON 백업 기능을 제공한다.

### 9.3 라우팅 및 배포

GitHub Pages 배포 시 클라이언트 라우팅의 새로고침 오류를 피하기 위해 Hash Router 사용을 권장한다.

Vercel을 선택하는 경우 적절한 SPA 라우팅 설정을 적용할 수 있다.

최소 실행 환경:

- Node.js 기반 개발 환경
- GitHub 원격 저장소
- 정적 파일을 호스팅할 배포 환경

MVP는 데이터베이스와 AI API 호출 없이 구동되어야 한다.

## 10. 주요 수용 기준 (Acceptance Criteria)

### AC-01. 면접 기록 생성

Given: 사용자가 메인 화면에 접속한다.  
When: 새 면접 기록을 선택하고 필수 정보를 입력한다.  
Then: 새로운 면접 기록이 생성되고 질문 입력 화면으로 이동한다.

### AC-02. 질문 기록

Given: 사용자가 질문 입력 화면에 있다.  
When: 질문과 답변을 입력하고 질문 추가 버튼을 누른다.  
Then: 기존 입력값이 유지되면서 새로운 질문 카드가 생성된다.

### AC-03. 중단 후 복원

Given: 사용자가 면접 기록을 작성하고 있다.  
When: 페이지를 새로고침하거나 브라우저를 닫았다가 다시 연다.  
Then: 동일한 브라우저에서 저장된 초안을 이어서 작성할 수 있다.

### AC-04. 프롬프트 생성

Given: 면접 기본 정보와 하나 이상의 면접 질문이 입력되어 있다.  
When: AI 프롬프트 생성 버튼을 누른다.  
Then: 입력값이 모두 반영된 프롬프트가 생성된다.

### AC-05. 프롬프트 복사

Given: 프롬프트가 생성되어 있다.  
When: 복사 버튼을 누른다.  
Then: 생성된 텍스트가 클립보드에 복사된다.

### AC-06. 입력 내용 수정

Given: 프롬프트가 이미 생성되어 있다.  
When: 사용자가 이전 질문의 답변을 수정한다.  
Then: 수정된 내용으로 프롬프트를 다시 생성할 수 있다.

### AC-07. 개인정보 검토

Given: 사용자가 AI 서비스에 기록을 전달하려 한다.  
When: 프롬프트 내보내기 화면에 진입한다.  
Then: 외부 AI 서비스에 공유될 내용과 개인정보 검토 안내를 확인할 수 있다.

### AC-08. AI 분석 결과 저장

Given: 사용자가 외부 AI에서 회고 결과를 받았다.  
When: 해당 결과를 서비스에 붙여넣고 저장한다.  
Then: 원래 면접 기록과 연결된 분석 결과를 다시 열람할 수 있다.

### AC-09. 백업 및 복원

Given: 사용자가 저장된 면접 기록을 가지고 있다.  
When: JSON 백업 파일을 내보내고 다시 가져온다.  
Then: 면접 정보와 질문, 회고 메모가 유지된다.

### AC-10. 모바일 이용

Given: 사용자가 모바일 브라우저에서 접속한다.  
When: 질문을 입력하고 프롬프트를 생성한다.  
Then: 가로 스크롤이나 레이아웃 깨짐 없이 주요 기능을 이용할 수 있다.

## 11. 제품 성공 지표

초기 MVP에서는 외부 사용자 추적 없이 기능 완성도와 사용성 중심으로 검증한다.

**핵심 성공 기준**

- 면접 질문 1개 이상으로 유효한 프롬프트 생성 가능
- 10개 이상의 질문도 안정적으로 저장 및 생성
- 새로고침 후 작성 내용 정상 복원
- 프롬프트 복사 및 Markdown 출력 정상 동작
- 개인정보가 외부로 자동 전송되지 않음
- 모바일 주요 사용자 흐름 정상 작동

**사용성 검증 목표**

- 3개 질문을 기록한 사용자가 5분 안에 첫 프롬프트를 생성할 수 있는지 테스트
- 개발 지식이 없는 사용자가 안내만으로 생성 과정을 완료할 수 있는지 확인
- 회고 질문이 과도하게 반복되거나 작성 부담을 높이지 않는지 확인

향후 사용자 동의를 기반으로 익명화된 분석 데이터를 수집하게 된다면 프롬프트 생성 완료율, 중도 이탈 구간, 재방문율 등을 검토할 수 있다.

## 12. 개발 우선순위 및 로드맵

### Phase 1 — Core MVP

목표: 면접 기록을 AI 분석 프롬프트로 변환하는 최소 제품 완성.

- 프로젝트 초기 설정
- 메인 화면
- 면접 기본 정보 입력
- 질문 카드 CRUD
- 가이드형 회고 입력
- 프롬프트 생성 엔진
- 프롬프트 미리보기 및 복사
- LocalStorage 자동 저장
- 반응형 디자인
- GitHub 저장소 및 공개 배포

**완료 기준:** 사용자가 면접 기록을 작성하고 실제 AI 분석 요청까지 진행할 수 있어야 한다.

### Phase 2 — Reflection Archive

목표: 일회성 프롬프트 생성기가 아닌 지속적인 회고 도구로 발전.

- 다중 면접 기록 관리
- 질문별 태그 및 필터
- AI 회고 결과 저장
- Markdown / JSON 내보내기
- 이전 기록 수정
- 면접별 인사이트 비교
- 입사 의향 및 조직 적합성 회고 강화

### Phase 3 — AI Integrated Experience

목표: 사용자가 다른 AI 서비스로 이동하지 않아도 회고할 수 있는 경험 제공.

- 서버 측 AI API 연동
- AI 제공자 선택
- 자동 회고 결과 생성
- 답변별 추가 질문 생성
- 면접 간 반복 약점 분석
- 회고 결과 보고서 생성

AI API 연동 시에는 백엔드 기반 키 관리, 인증, 요청량 제한, 비용 관리, 데이터 보존 정책, 이용자 동의 체계를 먼저 마련해야 한다.

## 14. 품질 관리 및 예외 처리

반드시 처리해야 할 예외 상황:

- 질문을 입력하다가 페이지를 새로고침하는 경우
- 일부 질문만 입력한 경우
- 면접관 반응이 기억나지 않는 경우
- 긴 답변을 작성하는 경우
- 기록을 실수로 삭제하려는 경우
- 클립보드 복사가 실패한 경우
- 브라우저 저장 용량이 부족한 경우
- 백업 JSON 파일 형식이 잘못된 경우
- 외부 AI 서비스 링크가 열리지 않는 경우
- AI 회고 결과를 저장하지 않은 채 페이지를 벗어나는 경우

사용자 기록 삭제 전에는 확인 절차를 제공한다.

저장 실패 시 사용자에게 명확한 오류 메시지를 표시한다.

## 15. 제품 원칙

**원칙 1 — 사용자의 기억을 왜곡하지 않는다.**

실제 질문과 답변은 사용자의 기록을 그대로 보존한다.

**원칙 2 — AI는 평가 보조 도구다.**

AI의 분석은 공식 면접 평가나 합격 결과가 아니다.

**원칙 3 — 불확실성을 숨기지 않는다.**

면접관의 의도, 표정, 조직문화 등에 대한 해석은 추정임을 구분한다.

**원칙 4 — 사용자는 평가 대상인 동시에 평가 주체다.**

사용자의 답변 분석과 조직 적합성 회고를 동일하게 존중한다.

**원칙 5 — 기록의 소유권과 통제권은 사용자에게 있다.**

작성된 내용은 사용자가 열람, 수정, 삭제, 내보낼 수 있어야 한다.

## 16. 최종 제품 정의

AFTERVIEW는 AI가 합격 여부를 예측해 주는 서비스가 아니다.

면접이 끝난 지원자가 자신의 경험을 쉽게 기록하고, 기록을 체계적으로 구조화하여 다양한 AI로 분석할 수 있도록 돕는 **면접 회고 프롬프트 빌더이자 개인 커리어 아카이브**다.

MVP의 성공은 화려한 AI 기능의 수가 아니라 다음 세 가지를 얼마나 자연스럽게 연결하느냐로 판단한다.

**기억하기 → 구조화하기 → 회고하기**

이를 바탕으로 추후 여러 면접의 경험을 축적하고 성장 패턴을 확인할 수 있는 커리어 리플렉션 플랫폼으로 확장한다.

**최종 제품 메시지**

"합격을 위한 준비만큼, 끝난 면접을 돌아보는 시간도 중요하니까."

**AFTERVIEW — Every interview leaves something behind.**
